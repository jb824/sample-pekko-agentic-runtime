## Findings

### 1. Medium: A Consumer That Never Returns Permanently Blocks That Consumer Worker

**File:** `runtime/src/main/java/com/example/agent/runtime/consumer/ConsumerWorkerActor.java`
**Lines:** `160-169`, `172-175`

The timeout handler now leaves `inFlight` set until the original `CompletableFuture` completes. This fixes the prior concurrency issue, but it also means `processingTimeout()` is warning-only. If `AgentConsumer.onAgentCompleted(...)` hangs forever, the worker never drains `pending`; once `maxQueuedEvents` is reached, every later event for that logical consumer is dropped.

**Scenario:** An audit consumer blocks indefinitely on a downstream service or deadlocked client. After the configured timeout, the worker logs the timeout but remains busy forever. Future `AgentCompletedEvent`s accumulate up to `CONSUMER_QUEUE_SIZE`, then are dropped for that consumer.

**Suggested fix:** Make this behavior explicit in the `AgentConsumer` contract, or add a cancellation/terminal policy. If exact per-consumer serial processing is required, the safest option is a cancellable/interruptible consumer contract and a timeout path that can conclusively end the invocation before draining the next event.

---

### 2. Low: Validation-Failure Consumer Dispatch Can Be Lost During Immediate Runtime Shutdown

**File:** `runtime/src/main/java/com/example/agent/api/AgentRuntime.java`
**Lines:** `79-88`, `135-157`

Validation failures are dispatched with `consumerRegistry.tell(...)`, then `run(...)` immediately returns a completed future. There is no acknowledgement that the registry or worker accepted the event. If a caller closes the runtime immediately after the returned future completes, the actor system can terminate before the consumer processes the validation-failure event.

**Scenario:** A CLI or short-lived job calls `runtime.run(...).toCompletableFuture().join()` for an unsupported task inside try-with-resources, then exits the block immediately. The failed `AgentResult` is returned, but the audit consumer may not observe the corresponding `AgentCompletedEvent` before shutdown.

**Suggested fix:** If consumer delivery is part of the runtime completion guarantee, introduce an enqueue acknowledgement from `AgentConsumerRegistryActor` and wait for it before returning validation failures. If consumers are intentionally best-effort, document that `run(...)` completion does not mean consumer delivery has happened.
