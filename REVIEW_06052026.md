# REVIEW_06052026: Consumer Infrastructure for the Pekko Agent Runtime

## 1. Goal

Provide a general-purpose **consumer infrastructure** in the runtime that client
applications extend in their own modules to build post-execution evaluation agents,
guardrails, metrics collectors, audit trails, or any other side-effect pipeline.
The runtime ships no opinions about what a consumer does.

This mirrors the akka-agents model where `Consumer` is an SDK-provided infrastructure
component and `EvaluationConsumer extends Consumer` is the application-level
implementation — except here everything is explicit Pekko Typed actors instead of
managed SDK components.

---

## 2. Reference: akka-agents Pattern

```
TaskEntity (EventSourced)
  └── emits TaskEvent.TaskCompleted
          │
          ▼
EvaluationConsumer extends Consumer          ← reactive, event-driven
  ├── ComponentClient.forTask(taskId).get()  ← fetch completed snapshot
  ├── EvaluatorAgent::evaluate               ← LLM-as-judge (custom, application-level)
  └── ToxicityEvaluator::evaluate            ← built-in SDK guardrail
```

Key design properties of the akka-agents consumer:

- **Async and non-blocking** — runs after the caller receives its reply; never delays the response.
- **Event-driven** — driven by the event journal via `@Consume.FromEventSourcedEntity`. No polling.
- **Composable** — multiple evaluators called inside one consumer handler.
- **Separable** — `EvaluatorAgent` is a distinct class with its own LLM prompt. The consumer is just wiring.
- **At-least-once delivery** — consumers must be idempotent; duplicates are possible.

The **runtime** provides `Consumer` (the infrastructure). The **application** provides
`EvaluationConsumer extends Consumer` (the logic). This project follows the same split.

---

## 3. What the Runtime Provides (Infrastructure Only)

| Component | Purpose |
|---|---|
| `AgentCompletedEvent` | Immutable event record published on every completed request |
| `AgentConsumer` | Abstract class clients extend — the SPI boundary |
| `ConsumerEffect` | Return type of `onAgentCompleted` — `done()` or `fail(reason)` |
| `AgentConsumerRegistryActor` | Internal actor: manages all registered consumers, routes events |
| `ConsumerWorkerActor` | Internal actor: one per registered consumer, isolates execution |
| `AgentRuntime.Builder.consumer(...)` | Registration API |

**The runtime ships zero implementations of `AgentConsumer`.** No LLM judge, no
toxicity patterns, no guardrail deny-lists, no evaluation result storage. Those are
application concerns, not runtime concerns.

---

## 4. What the Runtime Does NOT Provide

The runtime deliberately omits:

- LLM judge / evaluator logic
- Toxicity pattern lists or guardrail deny-lists
- Pre-execution input interceptors (can be added as a follow-on)
- Evaluation result storage
- Any `EvaluationConfig` with domain-specific fields

These belong in the client application module (`example/` or the client's own service).

---

## 5. Concurrency Model

- Each `onAgentCompleted(event)` call is **one atomic processing transaction**.
- `ConsumerWorkerActor`'s mailbox provides natural backpressure: events queue behind
  the current invocation. One event is processed at a time per consumer.
- Multiple registered consumers are **fully independent** — each has its own
  `ConsumerWorkerActor` and progresses in parallel with other consumers.
- No automatic fan-out within a single consumer.
- **At-least-once delivery** (especially relevant with the Cassandra persistence-query
  path): consumers must be idempotent. Duplicates are possible.

Idempotency key pattern:

```
consumerId + requestId → at most one side-effect
```

## 6. SPI Design

### 6.1 `AgentCompletedEvent`

**New file:** `runtime/src/main/java/com/example/agent/runtime/consumer/AgentCompletedEvent.java`

```java
package com.example.agent.runtime.consumer;

import com.example.agent.runtime.AgentStatus;
import java.time.Instant;
import java.util.List;

public record AgentCompletedEvent(
    String requestId,        // idempotency key for the consumer
    String tenantId,
    String gatewayName,
    String originalInput,
    String finalOutput,
    AgentStatus status,
    List<String> sources,
    long latencyMs,
    Instant completedAt
) {}
```

`requestId` is the consumer's idempotency key. Clients check whether they have already
processed this `requestId` before doing expensive work.

Events are published on **all** terminal paths: `COMPLETED`, `FAILED_SYSTEM`, `TIMEOUT`,
and `POLICY_REJECTED`. This lets consumers track failure rates, not only successes.

---

### 6.2 `ConsumerEffect`

**New file:** `runtime/src/main/java/com/example/agent/runtime/consumer/ConsumerEffect.java`

```java
public final class ConsumerEffect {

    public static ConsumerEffect done()              { ... }
    public static ConsumerEffect fail(String reason) { ... }

    public boolean isDone()                          { ... }
    public Optional<String> failureReason()          { ... }
}
```

Equivalent to Akka SDK's `effects().done()`. Returning `fail(reason)` signals that the
consumer could not process this event — the runtime logs the failure and continues. No
automatic retry in v1.

---

### 6.3 `AgentConsumer`

**New file:** `runtime/src/main/java/com/example/agent/runtime/consumer/AgentConsumer.java`

```java
public abstract class AgentConsumer {

    // Stable, unique identifier for this consumer.
    // Used as the idempotency namespace: consumerId + requestId.
    public abstract String consumerId();

    // Called by the runtime once per terminal AgentResult.
    //
    // Runs on a dedicated worker thread — blocking (e.g. CompletableFuture.get(),
    // HTTP calls) is safe. Must be idempotent: at-least-once delivery means
    // duplicate events are possible.
    public abstract ConsumerEffect onAgentCompleted(AgentCompletedEvent event);

    // Override to adjust the per-invocation processing deadline.
    // If onAgentCompleted does not complete within this duration, the runtime
    // logs a warning and moves on to the next event.
    public Duration processingTimeout() {
        return Duration.ofSeconds(30);
    }
}
```

Clients extend this class and inject whatever dependencies they need (LLM clients,
metric registries, stores) via their own constructor. The runtime calls only
`onAgentCompleted`.

## 7. Internal Runtime Actors

### 7.1 `AgentConsumerRegistryActor`

**New file:** `runtime/src/main/java/com/example/agent/runtime/consumer/AgentConsumerRegistryActor.java`

One singleton actor per `ActorSystem`. Spawned inside `Behaviors.setup` during
`AgentRuntime` bootstrap alongside `LlmWorkerActor`, `ToolRegistryActor`, etc.

Responsibilities:

- Holds `Map<String, ActorRef<ConsumerWorkerActor.Command>>` keyed by `consumerId`.
- On `Dispatch(event)`: forwards the event to every registered worker actor.
- On `Register(consumer)`: spawns a `ConsumerWorkerActor`, adds to map. If a consumer
  with the same `consumerId` is already registered, stops the old worker and replaces it.
- On `Unregister(consumerId)`: stops the worker, removes from map.

**Message protocol:**

```java
public sealed interface Command
    permits Register, Unregister, Dispatch {}

public record Register(AgentConsumer consumer)     implements Command {}
public record Unregister(String consumerId)        implements Command {}
public record Dispatch(AgentCompletedEvent event)  implements Command {}
```

**Failure isolation:** Registry uses `watchWith` on each worker. If a worker crashes,
the registry logs a warning and removes the dead entry. The registry itself does not
crash. The supervisor strategy for worker actors is `restart` with a backoff to handle
transient consumer errors.

---

### 7.2 `ConsumerWorkerActor`

**New file:** `runtime/src/main/java/com/example/agent/runtime/consumer/ConsumerWorkerActor.java`

One actor per registered `AgentConsumer`. Processes events from its mailbox **one at
a time** — actor mailbox semantics provide natural backpressure.

For each `Process(event)` message:

1. Schedules `ProcessingTimeout(requestId)` via `scheduleOnce(consumer.processingTimeout())`.
2. Runs `consumer.onAgentCompleted(event)` via `CompletableFuture.supplyAsync(...)` on
   the shared bounded consumer executor.
3. Pipes the result back to self via `pipeToSelf`.
4. On `WrappedResult`: cancels the timeout, logs pass/fail, becomes ready for next event.
5. On `ProcessingTimeout`: logs a warning, abandons the in-flight invocation, becomes
   ready for the next event.

**The consumer's `onAgentCompleted` runs on a worker thread, not the actor dispatcher.**
Blocking inside `onAgentCompleted` is safe.

**Message protocol:**

```java
public sealed interface Command
    permits Process, WrappedResult, ProcessingTimeout {}

public record Process(AgentCompletedEvent event)   implements Command {}

private record WrappedResult(
    String requestId,
    ConsumerEffect effect,
    Throwable error)                               implements Command {}

private record ProcessingTimeout(String requestId) implements Command {}
```

## 8. Changes to Existing Components

### 8.1 `DefaultAgentSystemExecutorActor`

**File:** `runtime/src/main/java/com/example/agent/runtime/agent/DefaultAgentSystemExecutorActor.java`

**Changes:**

- Add `ActorRef<AgentConsumerRegistryActor.Command> consumerRegistry` as a nullable
  constructor parameter. Nullable means: no consumers registered → no dispatch.
- Add `long startTimeMs` field, set in `onStart`.
- In `onGatewayResponse`, after `state.replyTo().tell(agentResult)`:

```java
if (consumerRegistry != null) {
    consumerRegistry.tell(new AgentConsumerRegistryActor.Dispatch(
        new AgentCompletedEvent(
            state.request().requestId(),
            state.request().tenantId(),
            state.system().entrypoint().name(),
            state.request().input(),
            answer,
            AgentStatus.COMPLETED,
            state.distinctSources(),
            System.currentTimeMillis() - startTimeMs,
            Instant.now()
        )
    ));
}
```

- Also dispatch on `onExecutionTimeout` (status `TIMEOUT`) and on the failure branch
  of `onGatewayResponse` (status `FAILED_SYSTEM`) with empty `finalOutput`.

The dispatch is **fire-and-forget** — it adds zero latency to the response path and
does not participate in the executor's own timeout.

### 8.2 `GatewayActor`

### 8.3 `AgentRuntime.Builder`

**File:** `runtime/src/main/java/com/example/agent/api/AgentRuntime.java`

**Change:** Add `consumer(AgentConsumer)` builder method:

```java
private final List<AgentConsumer> consumers = new ArrayList<>();

public Builder consumer(AgentConsumer consumer) {
    this.consumers.add(Objects.requireNonNull(consumer));
    return this;
}
```

In `build()`, inside `Behaviors.setup`, spawn the registry as a sibling of
`GatewayActor` before calling `GatewayActor.create(...)`:

```java
ActorRef<AgentConsumerRegistryActor.Command> consumerRegistry = null;
if (!consumers.isEmpty()) {
    consumerRegistry = context.spawn(
        AgentConsumerRegistryActor.create(consumers, config.consumerThreads()),
        "agent-consumer-registry"
    );
}
return GatewayActor.create(
    llmWorker, toolRegistry, memoryRegistry, ragRuntime,
    consumerRegistry,    // nullable — no consumers = no routing overhead
    ragEnabled, ragTopK, ragMaxContextChars,
    config.workflowTimeout(), config.toolTimeout(),
    config.maxConcurrentRequests()
);
```

Spawning inside `Behaviors.setup` ensures the ref is available before
`GatewayActor.create` is called, avoiding the post-creation timing problem that
affects `system.systemActorOf(...)`.

**Registration usage pattern:**

```java
AgentRuntime runtime = AgentRuntime.builder()
    .chatModel(model)
    .consumer(new EvaluationConsumer(myLlmClient))   // client-defined
    .consumer(new AuditConsumer(auditStore))          // client-defined
    .consumer(new MetricsConsumer(metricsRegistry))   // client-defined
    .build();
```

## 9. Updated Architecture

```
HTTP / gRPC
    │
GatewayActor  (capacity gate)
    │  spawns per-request
    ▼
DefaultAgentSystemExecutorActor
    ├── AgentStepActor  (ReAct loop)  × N
    │     ├── LlmWorkerActor
    │     └── ToolRegistryActor → ToolActors
    ├── RagRuntimeActor
    ├── AgentMemoryRegistryActor
    │
    ├── reply AgentResult ──────────────────────────► replyTo  (caller unblocked here)
    │
    └── [fire-and-forget] Dispatch(AgentCompletedEvent)
                                │
                    AgentConsumerRegistryActor          ← runtime infrastructure
                         │  (forwards to all workers)
                         ├── ConsumerWorkerActor  [consumer-A]   ← client's consumer A
                         │     sequential per event, bounded thread
                         ├── ConsumerWorkerActor  [consumer-B]   ← client's consumer B
                         │     independent, parallel with A
                         └── ConsumerWorkerActor  [consumer-N]
```

## 10. Example Consumer (lives in `example/`, not `runtime/`)

A reference implementation showing how a client extends the SPI.
**This is not shipped with the runtime.**

```java
// example/src/main/java/com/example/agent/EvaluationConsumer.java
public class EvaluationConsumer extends AgentConsumer {

    private static final Logger log = LoggerFactory.getLogger(EvaluationConsumer.class);

    private final MyLlmClient llmClient;   // injected by the client application

    public EvaluationConsumer(MyLlmClient llmClient) {
        this.llmClient = llmClient;
    }

    @Override
    public String consumerId() {
        return "evaluation-consumer";
    }

    @Override
    public ConsumerEffect onAgentCompleted(AgentCompletedEvent event) {
        if (!event.status().isSuccess()) {
            return ConsumerEffect.done();   // skip failed requests
        }

        // Idempotency: client-owned store keyed by consumerId + requestId
        if (alreadyEvaluated(event.requestId())) {
            return ConsumerEffect.done();
        }

        // LLM-as-judge: entirely the client's own logic and LLM client
        JudgeResult judgement = llmClient.judge(event.originalInput(), event.finalOutput());
        if (judgement.passed()) {
            log.debug("LLM judge passed for request [{}]", event.requestId());
        } else {
            log.warn("LLM judge failed for request [{}]: {}",
                event.requestId(), judgement.explanation());
        }

        markEvaluated(event.requestId());
        return ConsumerEffect.done();
    }
}
```

The consumer owns its LLM client, idempotency store, and logging. The runtime provides
only the event delivery infrastructure.

## 14. Testing Strategy

All actor tests follow the existing project pattern:
`ActorSystem<Void>` + `system.systemActorOf` + `AskPattern.ask` + blackhole/spy behaviors.

| Test | What it verifies |
|---|---|
| `ConsumerWorkerActorTest` | Event delivered to consumer; `done()` logged; timeout path abandons stale invocation and accepts next event |
| `AgentConsumerRegistryActorTest` | `Dispatch` reaches all registered workers; unregistered consumer no longer receives events; double-register replaces old worker |
| `DefaultAgentSystemExecutorActorTest` (update) | `AgentCompletedEvent` dispatched to registry after `AgentResult` sent; dispatched on timeout and failure paths; not dispatched if `consumerRegistry` is null |
| `GatewayActorTest` (update) | Consumer registry receives dispatch when executor completes normally; no dispatch on capacity-exceeded rejection |
| `AgentRuntimeIntegrationTest` (new) | End-to-end: `.builder().consumer(spy)` → `run(...)` → spy consumer's `onAgentCompleted` called with correct `requestId` and `status` |

Consumer actor tests use a `SpyConsumer extends AgentConsumer` backed by a
`CountDownLatch` or `CompletableFuture` to assert that `onAgentCompleted` was called
with the expected event — no live LLM calls required.
